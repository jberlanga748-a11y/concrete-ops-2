## Purpose

This packet gives one good-fit contractor a clear way to say yes to a narrow Apex HQ founder pilot without implying public self-serve SaaS, automated billing, legal approval, enterprise support, accounting replacement, guaranteed leads, or AI autopilot.

The pilot offer is:

```text
One real contractor workflow, guided by the founder, for 14 days. We set up the workflow together, check value on Day 3 and Day 10, then continue, adjust, or stop.
```

## Pilot Fit Gate

Offer this only when all are true:

- Contractor has active leads, estimates, jobs, field proof, reports, or follow-up pain.
- Owner/admin will test one workflow personally.
- Field user or foreman can try one simple action if the workflow includes field work.
- Contractor accepts the founder-led support boundary.
- Contractor understands this is a controlled pilot, not public self-serve launch.
- Contractor is not buying guaranteed leads, accounting, payroll, custom software, or AI automation.

Do not offer this when the buyer needs:

- guaranteed leads, jobs, revenue, or payment speed
- automatic text/email sends
- automatic bid submission
- accounting, tax, payroll, or QuickBooks replacement
- enterprise SLA, SSO, SCIM, security questionnaire commitments, or procurement claims
- custom feature promises before using the current workflow

## Manual Payment Path

No Stripe, checkout, self-serve billing, card capture, subscription automation, invoice automation, dunning, or automatic plan changes are included in Build 1A.

If the contractor chooses to continue after the value review:

1. Confirm the package direction in writing.
2. Confirm the monthly founder price in writing.
3. Use an approved manual payment path outside Apex HQ, such as a manually issued invoice, ACH instructions, check, or another founder-approved manual method.
4. Record the payment expectation in the pilot notes.
5. Do not change package, role, billing, or production configuration automatically.

Safe wording:

```text
If the pilot proves useful and you want to keep it, we can continue manually at the founder price we agreed to. I am not setting up automatic billing or a long contract for this pilot.
```

## Pilot Scope

Pick exactly one workflow:

- lead or opportunity follow-up
- estimate to proposal readiness
- approved estimate to job setup
- job schedule to field handoff
- photo, upload, daily report, or proof capture
- owner review and missing-item follow-up

The default workflow to sell first is:

```text
lead/estimate -> job setup -> field handoff -> photo/report proof -> owner review -> follow-up
```

## Included

- one selected workflow
- owner/admin setup support
- one field user or foreman setup when the workflow needs field proof

## Support Terms

Support is founder-led and scoped to the selected workflow.

Support owner: John

Support intake captures:

- company
- user name and role
- page/workflow
- issue summary
- blocker level
- screenshot or short recording when practical
- workaround
- next promised follow-up time
- whether the issue blocks the selected pilot workflow

Priority guide:

| Priority | Definition | Founder response posture |
| --- | --- | --- |
| P0 | Login outage, data exposure concern, role/security concern | Same day when possible; pause pilot workflow if needed |
| P1 | Selected pilot workflow blocked | Same business day when practical |
| P2 | Workaround exists or non-pilot workflow affected | Next check-in or next practical work block |
| P3 | Training, copy, polish, future idea | Log for later; no custom-build promise |

This is not an enterprise SLA.

## Onboarding Checklist

Day 0 kickoff:

- Confirm one workflow.
- Confirm owner/admin and field user, if applicable.
- Confirm support channel and support owner.
- Confirm first record to use.
- Confirm 1-3 success criteria.
- Confirm no sensitive data outside the selected workflow is needed.
- Confirm Day 3 and Day 10 times.
- Confirm manual payment path only if continuing after value review.

Day 1 setup:

- Owner/admin can log in.
- Owner/admin can find the selected workflow.
- First record is visible or ready to create.
- Field user can reach Field Mode if included.
- Field role cannot see leads, estimates, pricing, margins, settings, AI Office, package, admin, or other-company data.

Day 2 first action:

- Owner/admin completes one workflow step.
- Field user completes one simple proof/report/upload action if included.
- Any blocker is logged with priority.
- No new scope is added unless it protects the selected workflow.

## Day 3 Check-In

Goal: remove friction before the pilot drifts.

Questions:

- Did owner/admin log in without help?
- Did the selected workflow make sense?
- Did the field user complete the agreed action, if applicable?
- What still went through text, paper, memory, or spreadsheet?
- What was confusing?
- Did Apex HQ reduce any chasing or missing information?
- Should we continue, narrow, adjust, or stop?

Day 3 decision:

```text
Continue / narrow / adjust / stop
```

## Day 10 Value Review

Goal: decide whether the workflow is valuable enough to keep using.

Questions:

- What did Apex HQ help organize?
- What stayed clunky?
- Did it help with estimates, job handoff, field proof, owner review, or follow-up?
- Did it reduce chasing or make review faster?
- Would you pay to keep this workflow?
- Which package direction fits what you used?
- Should we continue, adjust, stop, or test one next workflow?

Continue only when:

- at least one written success criterion was met
- support load is manageable
- contractor understands the next price and scope
- no custom feature promise is required to justify continuing

## Success Criteria Menu

Pick 1-3 and write them into the order form.

- Owner can find the current job/proof without searching text messages.
- One estimate or proposal is cleaner and easier to review.
- One approved estimate is ready for job handoff.
- One job is visible with enough field context to start.
- One field photo, upload, report, checklist, or proof item comes back through Apex HQ.
- One missing follow-up is caught before it is forgotten.
- Owner/admin says the selected workflow is worth continuing at the founder price.

Avoid success criteria that promise:

- guaranteed jobs
- guaranteed revenue
- guaranteed time savings
- guaranteed crew adoption
- guaranteed faster payment

## Close Script

```text
Based on what you told me, I would not try to switch everything. I would test [workflow] first.

We can do that as a 14-day founder pilot. I help set it up, we use it on real work, check in after Day 3, then do a Day 10 value review.

If it cleans up enough chasing or handoff work to be worth keeping, we continue manually at [price]/month for [package direction]. If it does not, we adjust or stop. No long contract, no automatic billing, and no pretending it solves things it does not.
```

## Claims To Avoid

Do not say:

- Apex HQ will get you more jobs.
- Apex HQ guarantees leads, revenue, or faster payment.
- Apex HQ replaces accounting, payroll, taxes, or QuickBooks.
- AI will run your business, price work, submit bids, send customers messages, or approve changes automatically.
- The product is public self-serve or enterprise-ready.
- We can build whatever you want during the pilot.
- Crews will definitely use it.
- You will save a specific number of hours.

Safe language:

```text
Apex HQ helps organize the work that is already happening: opportunities, estimates, job setup, field proof, owner review, and follow-up. The pilot is how we find out whether it helps your workflow enough to keep using.
```
